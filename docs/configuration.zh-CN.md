# 配置与权限

[English](configuration.md) | 简体中文 | [README](../README.zh-CN.md)

本文描述桥接插件 0.2.2。用 `harness_status` 检查当前配置和存储状态，用 `list_models` 查看当前允许调用方选择的模型。

## 模型选择

工具栏决定任务约束。桥接没有写死一个通用的 DeepSeek 模型名，可用供应商、模型和推理等级都来自 Harness。

| 模式 | 供应商 | 模型与推理等级 |
| --- | --- | --- |
| 单模型 | 锁定 | 锁定 |
| 供应商；调用方覆盖关闭（默认） | 锁定 | 工具栏默认值也是任务约束 |
| 供应商；调用方覆盖开启 | 锁定 | 调用方可在该供应商内选择受支持的模型和等级 |

通常不要在任务请求中填写 `provider`、`model`、`reasoningEffort`。只有用户明确要求、工具栏也允许覆盖时，才传模型或等级。显式值与约束冲突时返回 `CONFIG_CONFLICT`，不会静默改变所选路由。

字段为空时的实际规则：

- 单模型的供应商／模型回退到 Harness 当前默认选择。
- 供应商模式的供应商回退到该默认选择中的供应商。
- 供应商模式没有配置默认模型时，使用该供应商模型目录中的第一个模型。
- 推理等级回退到模型目录中的默认等级。锁定模式下，旧配置中不受支持的等级会报错。允许覆盖时，若工具栏等级不适用于调用方所选模型，则改用该模型默认值；调用方显式传入不支持的等级仍会报错。

如果需要可预测的模型路由，建议在工具栏明确选择，不依赖模型目录顺序的回退值。

## 设置何时生效

- 已运行任务保留启动时的配置快照。
- 排队任务取得执行额度和会话锁后，在启动前重新检查当前配置。
- 异步准备期间设置变化，可能直接返回冲突，避免在含混配置下开始。重试前先检查当前状态。
- 工具栏设置变化不会重启插件。关闭 MCP 开关不会紧急停止已经运行的任务；应使用任务取消或 Harness 自身控制。

回执区分 `requestedSelection`、`effectiveSelection`、`configVersion` 和 `configSource`。兼容旧客户端的顶层 provider／model 字段表示任务约束。只有在 Harness 的 `llm/stream` 事件中观察到实际请求信封后，才填写 `effectiveSelection`；此前为 `null`。它说明桥接观察到了什么，不证明供应商已经接收、完成或计费。

## 工作区选择

新建会话时，显式 `workspace` 优先于工具栏默认值，可以按 ID、标题或路径选择已有工作区。显式提供一个存在的目录，也可能为该目录创建 Harness 工作区。省略 `workspace` 时，必须已设置有效的工具栏默认工作区；桥接不会替换为调用方的当前目录。

用 `sessionId` 续聊时，工作区上下文来自已有会话。不要用 `workspace` 尝试移动已有会话。由其他 owner 持有的 live 会话会被拒绝接管。工作区选择本身不构成安全边界。

## 新会话权限

工具栏使用 Harness 官方权限预设，**只用于新建 MCP 会话**：

| 选择 | 预设 | 标准沙箱／审批策略 |
| --- | --- | --- |
| Harness 新会话默认值 | 桥接配置中为 `default` | 使用 Harness 当前新会话默认值 |
| 仅可查看 | `read-only` | `read-only` / `ask` |
| 工作区访问 | `workspace-write` | `workspace-write` / `ask` |
| 完全权限 | `danger-full-access` | `danger-full-access` / `never` |

迁移和配置默认值都是 `default`，它**不一定是只读**；请检查 `harnessDefaultPermission`。初次做只读试用时，应明确选择只读预设。

**完全权限会移除通常的沙箱限制，可能允许执行命令或修改工作区之外的文件。** 只有在理解并确实需要这种访问范围时才选择它。连接 MCP 客户端本身不需要完全权限。

新会话选择器不会覆盖续聊／恢复会话的权限，包括人在 Harness 中做过的调整，也不会修改 Harness 的全局默认值。所选预设不可用时会启动失败，不会回退到更宽权限。显式旧配置 `approvalMode` 仍可能改变桥接管理会话续聊时的审批策略；需要保留原策略时，应保持 `inherit`。

`never` 表示需要审批的请求被直接拒绝，不是“自动同意所有操作”。预设已允许的操作可能无需提出审批请求。单次批准不会转换为持续授权。

## 分开的审批层

1. MCP 客户端自己的规则，决定能否调用 `run_task`、会话管理或其他公开工具。
2. Harness 会话的沙箱与审批策略，控制被委派智能体的具体操作。
3. 操作系统提示和外部审核层仍然独立存在。

`approval/asked` 事件只能证明发生了审批请求，不能证明某个窗口真的显示过。任务报告等待审批时，请检查 Harness。不要用扩大执行权限的方式解决客户端超时。

### 旧配置迁移

- `autoApprove` 已被忽略，不作为授权来源。
- `approvalMode`（`inherit`、`ask`、`never`）保留后端兼容，显式 `ask`／`never` 也可用于受管理会话的续聊和恢复。新 UI 明确选择新会话预设时会把它重置为 `inherit`，让完整预设同时控制沙箱和审批。
- `providerAllowOverrides` 默认 `false`，旧配置缺失该字段时也是如此。这是相对于最初供应商模式的有意行为调整。

## 连接与环境变量

默认连接为本地 stdio → 中转脚本 → Windows 命名管道或 Unix socket → Harness 插件，不开启 TCP 端口。默认管道在 Windows 上为 `\\.\pipe\dsh-mcp-bridge-<用户名>`，其他平台为 `$DSH_HOME/mcp-bridge/bridge.sock`。

中转脚本使用 TLS 1.3 和从 token 派生的角色独立公钥锁定（`tls-pinned-v3`），验证对端后才转发 MCP。这认证的是共享 token 的持有者，不是 Windows 进程签名。即使传输已加密，仍需保护 token 和本地文件。

| 中转脚本环境变量 | 含义 |
| --- | --- |
| `DSH_HOME` | Harness 数据主目录，默认 `~/.dsh` |
| `DSH_MCP_BRIDGE_PIPE` | 指定管道／socket 地址；未指定则先读 `endpoint.json`，再用平台默认值 |
| `DSH_MCP_BRIDGE_TOKEN` | 私密 token 覆盖值；否则读取默认 token 文件 |
| `DSH_MCP_BRIDGE_WAIT_MS` | 连接重试窗口，单位毫秒，默认 `15000` |

Codex 可通过 `env_vars` 显式转发需要的非密钥变量，或在服务的 `env` 表中设置。遵循各客户端自身的环境变量语法，不要假设图形客户端一定继承终端环境。

宿主设置还包括 `pipePath`、`authTokenFile`、`preset` 和 `maxConcurrentTasks`（默认 `2`）。这些非工具栏的连接／运行时字段改变后，可能需要重载插件或重启。宿主自定义 token 文件路径不会自动被中转脚本读取，需要明确对齐配置，并保持任何密钥覆盖值私密。

可选 Streamable HTTP 默认关闭（`httpEnabled: false`）。启用后默认地址为 `http://127.0.0.1:8090/mcp`，使用 bearer token 认证。此可选 HTTP 监听没有由桥接提供 TLS 加密，不要将它暴露到不可信网络，也不要把 loopback 地址当成不同客户端之间的隔离。没有特殊需求时优先使用本地中转脚本。

存储和破坏性操作详见[任务与会话维护](usage.zh-CN.md)。
