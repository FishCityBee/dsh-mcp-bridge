# 0.2.1 桌面替换与验证

实际环境：Windows x64，已安装的 DeepSeek Harness **0.2.1-rc.2**，其 Electron **44.7.0** / Node **24.21.0**；Claude 中转脚本使用 Node **22.14.0**。

## 复现与修复

原来已安装的 0.1.0 和 Claude relay 都指向原仓库的 `dist-package`。实时 MCP 查询确认没有活动任务后，备份原目录并试装 0.2.0。官方桌面运行时在创建 PSK TLS 服务时抛出 `ERR_SSL_NO_CIPHER_MATCH`，导致插件后端未启动；普通 Node 的 OpenSSL 测试没有覆盖这个运行时差异。

先在实际 Electron 的 Node 模式运行原有 `tests/pipe-security.mjs`，得到同样的失败，保留失败证据。没有改动官方 CLI 对 desktop 专用配置的启动限制。

0.2.1 改为标准 TLS 1.3 双向公钥锁定：

- 从共享 token 通过 HMAC-SHA256、带角色和协议域的标签分别派生客户端和服务端 P-256 签名密钥。
- 证书在内存中生成，不需要 OpenSSL 可执行文件、外部 CA、静态私钥或新增依赖。证书只承载公钥，双方以预期 SPKI 锁定对端身份；TLS 本身验证签名私钥持有证明。
- `rejectUnauthorized:false` 仅跳过公共 CA 信任链验证。客户端在转发 MCP 前必须验证服务端 SPKI；服务端要求客户端证书，在接纳 MCP 前验证客户端 SPKI。无证书、错误密钥和角色反射均拒绝。
- 长期 token 和私钥不会发送到管道。最低 TLS 1.3，不兼容旧明文或 PSK 协议；端点声明为 `tls-pinned-v3`，插件与 relay 必须同时更新。
- 管道服务改为在 token 就绪后初始化，卸载中途不会在异步准备完成后重新启动监听。

这是共享 token 持有者认证，不是 Windows 进程签名认证。没有修改沙箱、管道 ACL 或权限策略，也没有声称完成跨账户攻击测试。

## 验证

实际运行并通过：

```powershell
npm run typecheck
npm run build
npm test
git diff --check
```

完整测试为 **33 smoke + 10 units + 30 regression + 8 pipe-security = 81 项**。保留了原管道抢占和错误密钥拒绝断言，错误密钥 fixture 只随正式协议改为公钥锁定，未移除失败断言；另增加证书加载、正常转发、错误客户端、缺失客户端证书、角色反射和 TLS 1.2 降级测试。

使用实际 Electron 启动相同的管道测试，设置 `DSH_TEST_RELAY_NODE` 指向 Node 22 的中转进程，**8 项再次全部通过**。这些只使用新建临时管道和随机测试密钥，不访问真实会话或真实 token。测试文件可直接由 Electron 的 `ELECTRON_RUN_AS_NODE=1` 模式运行，以防只测普通 Node 再次遗漏该差异。

实际桌面重新启动后，通过原仓库的正式 relay 连接，MCP 返回：

```json
{"server":{"name":"dsh-mcp-bridge","version":"0.2.1"}}
{"enabled":true,"mode":"provider","providerAllowOverrides":false,"approvalMode":"inherit","autoApprove":false,"legacyAutoApproveIgnored":true}
{"active":[]}
```

端点已更新为新的宿主 PID 和 `tls-pinned-v3`，状态没有 startupError / storageError。安装目录逐文件 SHA-256 与本次正式构建一致；临时启动诊断入口已被正式构建整体替换。

原 0.1.0 的独立 ZIP 备份及原目录保留。原仓库 `dist-package` 同时供桌面配置链接与 Claude relay 使用，不需要修改 Claude 的 MCP 配置。

## 尚未覆盖

本次已完成真实 Windows 桌面宿主启动和 MCP 连接验证，没有发起付费模型任务，也没有执行真实会话删除、权限持久变更、实际操作审批或完整 UI 设置交互验证。因此不把这些管道与只读状态检查称为模型路由或权限全链路验收。Claude 已有连接如断开，需要在 `/mcp` 中重新连接 `dsh-harness`。

参考：[TLS 证书请求与验证](https://nodejs.org/docs/latest-v22.x/api/tls.html#tlscreateserveroptions-secureconnectionlistener)、[读取对端 X.509 证书](https://nodejs.org/docs/latest-v22.x/api/tls.html#tlssocketgetpeerx509certificate)。
