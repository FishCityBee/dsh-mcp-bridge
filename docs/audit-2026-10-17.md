## 复核结论

原仓库仍是审核基准，8 项缺陷均存在；没有把 smoke 通过作为关闭依据。修复版本为 **dsh-mcp-bridge 0.2.0**。

| 问题 | 基准实际证据 | 0.2.0 处理及验证 |
|---|---|---|
| 单模型 / 供应商控制 | 供应商默认值可覆盖；owned/live 继续沿用旧路由 | 单一解析器；新增默认关闭的 `providerAllowOverrides`；显式冲突 `CONFIG_CONFLICT`。官方 `installModelSelection` 影响实际 waterfall；`llm/stream` 再核对请求。新建、owned、磁盘 resume、排队配置变化均断言实际请求参数 |
| 记录 B、实际 A | 同一 agent 的持久 header 仍路由到 p/a | 同会话锁内落实选择，真实信封是 q/c；非本插件拥有的 live 会话明确拒绝，不改 options、权限或 dispose |
| 自动批准实为拒绝 | 安装包实际 `never -> rejected` | 删除误导开关；`inherit/ask/never` 语义明确。只对本插件管理会话应用用户选择；沙箱不改。真实官方审批逻辑验证允许一次、拒绝、询问、取消 |
| ID 越界删除 | 真实目录存在即可递归删除；补齐分桶后遍历回归失败 | 单路径 ID + Windows 保留名检查；官方 stat 验证身份；核对后端根；每层 lstat/realpath/relative 拒绝链接、junction、相邻前缀及越界。缓存、pending-delete 同样拒绝不可信路径 |
| 近期活动误清理 | 老目录刚追加日志仍被批量筛选为过期 | 使用最高代有效日志的文件 mtime；压缩歧义或未知日志不支持自动过期。批量和自动清理共用，测试老目录新日志保留、真旧日志删除 |
| 批量删除默认过大 | 不传 mcpOnly 会选中个人会话 | schema、后端、前端、README 统一 true；false 显式包含个人会话。永久删除必须使用 60 秒预览令牌，固定 ID / 版本；新匹配项不扩入，已变化项要求重新确认 |
| 排队 / 准备中取消复活 | 等会话锁和 create 时取消后仍发送 | 生命周期 AbortController；锁后、额度后、异步创建/恢复后、发送前复核；终态 cancelled 不再改 running。覆盖等锁、创建、恢复、运行中取消 |
| 活动记录被 200 条裁剪 | 全量 sort/slice 丢老活动任务 | 全部活动保留，只有终态历史做 7 天 / 200 条裁剪；验证老活动 + 201 新终态、201 活动、冷加载和取消后的保留 |
| idle 当成功 | 模型终止 error 被写 done | 依任务事件基线用官方 `foldConsumedWork` 和 `turn/end` 分类；保存结构化 termination。终止模型错误 failed、重试恢复成功 done、界面停止 cancelled；无可信终止证据为 interrupted |
| 重载调度 / waiting_approval | 直接 follow 既不计额度也不恢复锁；从当前 seq 采样丢待审批 | 接纳等待恢复完成；live 任务占用并发额度并进入会话锁；从历史重建未决审批。只观察其他 owner 已存在的任务，不改其路由或权限 |
| resume 隐式唤醒 | 官方允许返回前启动恢复的 inbox | 首个 pre-step 启动门控；接纳持久化、监控和取消检查完成后才开放。专门模拟返回前自动唤醒，取消后无请求 |
| 持久化失败静默 | task / ledger 吞写入异常；首次接纳延迟 | 串行快照、文件 sync、原子 rename；重要接纳/终态显式等待。失败接纳不启动 agent；终态写盘失败保留真实业务结果并标 durability=degraded。ledger 共享首次 load Promise，串行更改，失败回滚自己的变更 |
| 前端旧响应覆盖 | load/save 没有版本守卫，失败回滚全量旧设置 | 读序号 + 本地 revision；写入按用户顺序串行，未完成编辑是独立覆盖层；失败只移除自己的编辑。测试读乱序、读与保存交错、前次失败后次成功 |
| Windows 管道身份 | 在临时 Windows 同名管道上，旧 relay 向假服务端发送随机测试 token | 双向 TLS PSK + 加密，PSK-only TLS 1.2 / AES-256-GCM，不允许证书或明文降级。测试被预占管道和错误 PSK 不得到 token/MCP；正常 MCP 走真实 Windows 管道。没有改 ACL，未测跨账户访问 |

第一组 11 个针对性反例用**未改动的原始源码与原始 relay**重新执行，结果 **0 通过 / 11 失败**。其中供应商覆盖默认关闭、拒绝非 owned live 是本次明确提出的新行为，并非全部属于旧版既有承诺。原始 33 项 smoke 全通过，不能否定这些失败。

## 配置与回执

- `requestedSelection` 是调用方显式参数；旧客户端可以继续省略 model / effort。`provider` 为兼容性新增可选参数，也只能等于锁定供应商。
- `effectiveSelection` 初始 null，仅在官方 `llm/stream` 分派边界看到实际信封后填写；同时记录 `selectionEvidence` 和 `requestCount`。这证明本地分派参数，不证明远端收到或计费。旧 provider/model 字段描述解析后的任务约束，不应再用作实际请求证据。
- `configVersion` 是无密钥配置快照的内容指纹，来源为 `toolbar-v2`；不是递增数据库版本。运行任务固定快照，排队任务重新解析；准备期间再变更则拒绝启动。
- 空等级使用该模型目录中的默认值。锁定模式中无效的旧配置明确报错；允许覆盖且调用方选择了不同模型时，才按该模型支持的等级/默认值解析。
- `providerAllowOverrides` 缺省 false 是新产品调整。原供应商默认值可覆盖的事实保留在迁移说明中。

## 授权边界与尚未实现的诉求

该精确上游的审批策略只有 ask、never；允许结果只有 allowed-once。**没有发现受支持的“同范围持续审批授权”保存/命中接口**，不能把 Auto preset 或 danger-full-access 误当范围授权。此次没有自建缓存、跨会话复制授权、关全局沙箱或自动点击允许。

旧 autoApprove 忽略并提示迁移。已有会话原来的 never 不会在 inherit 下被偷偷改成 ask；用户可明确选择 ask。新建 / owned 续用 / 本插件管理的磁盘恢复使用同一应用逻辑。非 owned live 会话的权限不修改。

诊断记录 taskId/sessionId、配置指纹、审批策略和来源、preset/sandbox、触发工具、官方结果、无可复用授权及前次单次允许等原因。审批历史先折叠，只有本任务事件进入本任务诊断；不记录审批原始参数、私密完整提示、API Key 或 token。`approval/asked` 只是审计请求；never 也会产生它，不能据此断言弹窗。

| 提示来源 | 此次能验证的范围 | 需要的后续定位 |
|---|---|---|
| Claude 是否允许调用 MCP | 测试通过真实 MCP SDK 完成调用；不更改用户 Claude 权限 | 窗口若出现在 taskId 产生前，先核对 Claude MCP 许可；不能当下游文件授权 |
| Harness 策略 / preset / 沙箱 | 精确版本代码和真实 ApprovalService 结果；新建、owned、磁盘恢复 | 在独立测试 profile 看 toolbar 与会话策略及 workspace 是否一致 |
| 路径 / 命令 / 工具 / 会话 / 范围变化 | 单次允许不记忆；扩大的操作仍进入真实 answerer | 该版不存范围命中，桥接不会猜测两次参数是否同范围 |
| Auto review / OS 权限 | 不绕过、不改权限；桥接没有这些确认源的直接观察接口 | 真实再次出现时按来源分别记录，不把所有弹窗归因于 approval/asked |
| 插件重载 / 应用重启 | 官方 owner 生命周期源码；恢复额度、锁、历史审批的离线回归 | 真实桌面 owner drain、重启后恢复和 UI 状态尚需独立 profile 联调 |

持续授权的后续方案是先升级到提供持久范围授权机制的官方 Harness 版本，或先取得明确范围接口规范再设计适配；需另行确认具体授权范围。本次未实施任何永久权限变更。

## 剩余限制与手工验收

1. **未进行真实 Harness 桌面端到端联调**。本机是受支持的 Windows x64，但此次只执行离线服务测试、真实官方审批实现及真实临时命名管道测试；没有把它们称为桌面 UI 联调，没有调用付费模型，也没有删除用户真实会话。
2. 在独立 DSH_HOME / 测试 profile 中同时更新 host 与 relay、重启 Harness。旧明文 relay 将连接失败；不得为兼容而开启降级。MCP 参数层继续兼容旧客户端。
3. 用本地无费用测试 adapter 验证单模型冲突零请求、供应商开关默认锁定、owned 切换及磁盘恢复；任务回执 effectiveSelection 与 adapter 捕获的信封对照。运行 A、排队 B、改配置并取消 B，确认 B 无 prompt；再测恢复自动唤醒。
4. 使用临时 workspace 分别单次允许、再次同操作、范围扩大、拒绝和取消；核对窗口属于 Claude、Harness、Auto review 还是 OS。单次允许再次询问属于该版机制，不能将它标成持续授权修复完成。
5. 只在专门新建的测试会话检查批量预览后新建/续聊、老目录新日志、重载等待审批与 owner 释放后的 pending delete。旧 pending-delete 绝对路径需重新确认，文件版本变化也需重新确认。
6. 文件删除使用 Node 高层路径 API 并在操作前重新核对；没有宣称可抵抗同账户恶意进程在检查与删除之间并发替换目录的所有竞态。非默认后端根或不受支持布局拒绝删除。更强的对抗性保证需要官方原子删除/租约 API 或平台 handle 级操作。
7. 写入已等待文件 sync 与原子 rename；没有进行断电实验，也不承诺 Windows 目录元数据在任意断电时都已落盘。存储错误显式阻止新接纳或标为降级；不是静默成功。
8. PSK 证明持有共享密钥，不是 Windows 进程签名/账户认证；同账户进程若已能读取 token 文件不在此边界之内。未修改或跨账户实测管道 ACL；这不是公网匿名认证绕过结论。可选 HTTP 的配置仍需按既有本地部署方式使用。
